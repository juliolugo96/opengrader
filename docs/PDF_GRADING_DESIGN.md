# PDF Grading Design

## Outcome

The PDF workflow adds manual grading for untrusted PDF submissions without
coupling documents to the automated code-job state machine. An instructor can
upload a PDF, define a rubric, record criterion scores and page comments,
finalize the grade, and download a feedback-preserving PDF.

## Contract

```text
authenticated PDF upload
  -> bounded streamed storage under a generated ID
  -> strict PDF validation and page-count limit
  -> durable draft record + audit event
  -> rubric scores and normalized page annotations
  -> finalized record
  -> original pages + PDF text annotations + embedded feedback JSON
```

- Uploads use `multipart/form-data` with `file`, `student_id`, and `title`.
- Client filenames are metadata only. Storage paths are generated by the server.
- The default limit is 10 MiB and 200 pages; both are configurable.
- Encrypted, empty, malformed, oversized, and over-page-limit PDFs are rejected.
- Rubric criterion IDs are unique and every saved grade supplies exactly one
  bounded score for every criterion.
- Annotation coordinates are normalized from the page's top-left so clients do
  not need to know PDF point dimensions.
- Finalized grades are immutable. Instructors must keep a grade in draft while
  editing.
- The exported PDF contains printable text annotations and an
  `opengrader-feedback.json` attachment containing the complete rubric,
  criterion feedback, overall feedback, and totals.

## API

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/v1/pdf-submissions` | Upload and validate a document |
| `GET` | `/v1/pdf-submissions` | List newest documents |
| `GET` | `/v1/pdf-submissions/{id}` | Retrieve grading state |
| `GET` | `/v1/pdf-submissions/{id}/document` | Stream the original PDF |
| `PUT` | `/v1/pdf-submissions/{id}/grade` | Save or finalize grading |
| `GET` | `/v1/pdf-submissions/{id}/feedback.pdf` | Export finalized feedback |

All routes require the existing bearer authentication. Uploads, draft saves,
and finalization add append-only audit events with resource type
`pdf_submission`.

## Security boundaries

OpenGrader never executes PDF content and never trusts its filename or MIME type as
proof of validity. Files are written in chunks, size-checked while streaming,
parsed in strict mode, rejected when encrypted, and stored outside the static
web root. PDF parsing is still a complex-file-format boundary; deployments
should keep `pypdf` current and apply reverse-proxy request limits as an outer
layer.
